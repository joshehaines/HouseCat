## 2. The event log

The save is an append-only list of `GameEvent`s (`Packages/HouseCatCore/Sources/HouseCatCore/Save`). An event records a fact: when (`at`, trusted game time), which game day (`day`, fixed at append so a later wake-time or time-zone change never re-buckets history), who (owner, co-owner, sitter), from where (app, widget, Watch, Mac, Siri) and what (`Kind`: fed, petted, placed item, bought for 120 Beans, claimed tier 7…). Nothing is stored as a counter.

**Deriving state.** `HouseholdState` is the fold of the events in log order (`apply`). Days are closed as time moves past them (`advance(to:)`); closing a day is where a missed day is counted (grace or loss), pause days are used, and the day's Beans settle with the Cat Club bonus. `resolved(through: today)` closes every day before today: that is the state screens and widgets read. Invalid events (spending Beans that are not there, claiming a tier not reached, placing an item not owned) are ignored, never trusted.

**Ordering and merging.** The log is ordered by (day, time, id). New events take `SaveLog.timestamp(for:)`, strictly after the newest event, so events appended while game time is paused keep their order. Devices merge by event id (`SaveLog.merge`): idempotent and order-independent, so any devices holding the same events derive the same state. CloudKit mirroring cannot enforce uniqueness, so duplicates are dropped on load.

**Snapshot and compaction.** Events older than 30 days (`Tuning.Save.compactionHorizonDays`) are folded into a snapshot (`SaveLog.compacted(before:)`): the full `HouseholdState` with the boundary day open. Compaction is deterministic, and a test checks that compacting at any boundary never changes the derived state. A late event from before the snapshot (a device offline for over a month) lands on the snapshot's open day.

**Content as input.** The fold takes a `RulesContext` built from `Content/` (gift pool, objective pools, seasons and their rewards, which items are paid). Changing `Tuning` or content re-derives history. Fine during development and beta; before launch, rules changes that would move past balances get a rules version on events (risk noted for the launch step).

**What the save holds about purchases.** Entitlements are never in the save. Three purchase-related facts are, because the derived state needs them and they grant nothing on their own:
- `passPurchased(season)`: recorded for the season running now when a verified StoreKit purchase of its pass (`housecat.pass.<passID>`, non-consumable) is heard (`GameSession.recordPass`), like `clubDayRecorded`: it opens that run's premium claims on every device and grants nothing by itself. Restore Purchases brings the product back, and the next run of the same season records it again.
- `clubDayRecorded`: written once a day while a verified Cat Club entitlement is live, so that day's +20% Beans and paid-track claims re-derive the same forever, even after the subscription lapses.
- `purchaseBeansGranted(transactionID, beans)`: the Beans in bundles and packs, counted once per store transaction however many devices record it.
Only the household owner's devices write these (see §6).

## 3. Time

- `GameDay`: a calendar date as days since 1970, with exact civil-date arithmetic (no `Calendar` in the rules).
- `DayClock`: wake time, bedtime, time zone. A game day runs from one wake time to the next (06:00 by default), so 02:00 belongs to the previous day. Summer-time changes are tested.
- `TrustedTime.now`: game time from the wall clock checked against a trusted anchor (a CloudKit `modificationDate` or StoreKit `signedDate` with the system uptime when it was read). A backwards jump holds game time still; a jump of more than a day ahead of the anchor pauses game time instead of punishing. The app calls it before appending any event.
- `SeasonCalendar`: December is always the Christmas season (1–28 December), with four-week seasons back to back the rest of the year; the season that meets 1 December takes the spare day or two.
- `DaySeed`: SplitMix64 seeded from the household seed, the day and a purpose, with its own range reduction, so the app, widget, Watch and Mac draw the same gift, objectives and cat schedule without talking, on any Swift version.

## 4. How state flows to scenes and widgets

```
 user action ──► TrustedTime.now ──► GameEvent ──► EventStore (SwiftData, App Group) ──► CloudKit private DB
                                                        │
                                   SaveLog.derive(through: today, context)
                                                        │
                                                 HouseholdState  (rules applied once, here)
                    ┌───────────────────┬───────────────┴──────────┬──────────────────────┐
              RoomScene / CatNode   WidgetRules.timeline     Watch complication     Mac menu bar
              (BehaviourTable picks (48 entries, 30 min,     (streak, fed?)         (Feed / Pet append
               activity + pose)      pose + streak)                                  events)
```

- **App.** On launch and on every append, the app loads the log, derives the state through today and hands value types to the scenes. `BehaviourTable.choose` turns mood × weather × personality × the room's furniture affordances into an activity and a pose; the scene animates it. A room with nothing to sit on gets a floor loaf and the `home.empty_room` line.
- **Widgets.** The widget reads the same SwiftData store from the App Group, derives the state and builds its timeline with `WidgetRules.timeline`: 48 entries 30 minutes apart, each with the streak and the visited-today pose. App Intents (Feed, Pet) append an event and reload the timeline. Widgets never fetch: weather comes from the app's cached forecast and the cat poses are pre-rendered PNGs in the App Group (the widget cannot run the coat shader).
- **Watch and Mac.** Both append events to the same iCloud save and derive the same state; neither has rules of its own.

### The visit (milestone 1)

```
 launch / back after an hour ──► Visit ──► ArrivalRules.showsExterior? ──► ExteriorScene (sky phase, season, door point)
                                   │                                              │ tap or 2.5 s: door opens, camera pushes in
                                   │   0.4 s later, behind the exterior:         ▼
                                   └──► GameSession.arrive() ──► greeting context (Greeting) from the state before
                                              │                  `arrived` appended, state derived again
                                              │                  mood × weather × personality × placed affordances
                                              ▼                  → BehaviourTable.choose
                                        RoomScene + CatNode ──► CatDirector plays the arrival: notice, run to the camera,
                                                                rub (haptic), walk to the chosen furniture, settle in a pose
```

Outside and back (20 Oct): Menu → Outside, or a tap on the living room's front door, calls `Visit.stepOutside()`, which builds the `ExteriorScene` for now with `looking` set (the camera draws back out of the doorway; nothing auto-advances) and keeps the `RoomScene` as it was; Go in, or a tap on the door, runs the usual push and presents that same room again. In both the cold open and the outside view `GameWorld.seatCat` puts the cat at a window: `WindowCatRules` (HouseCatCore) picks the window from the scene's measured windows (`scenes.json` "windows", `tools/asset-pipeline/scenes.py windows`) by the storey of the room it is in, the part of the day and what it is doing, and `ExteriorScene.seat` draws a `CatNode` in an `SKCropNode` cut to that window's glass, tinted by an effect-node shader.

The room scene is the house view: `RoomScene` builds a `RoomNode` per room of the storey on screen from a `HouseModel` (the home's plan in `assets/rooms/houses.json` plus the save's opened rooms, placed furniture and surfaces), on a ground plane, with the cat in the active room. Decorate mode lives in `RoomScene+Decorate.swift`: hit-test, snap with `PlacementRules.snap`, colour with `PlacementRules.fits`, and report a `DecorateChange` that `GameSession.record` appends as `itemMoved` / `itemStored`.

Care and idle: `GameSession.feed()` / `pet(taps:)` append `fed` / `petted` and pick the line with `CareLines`; the scene's `send(_:)`, `react(_:)` and `nextActivity` hook carry them out. `Sound` (Shared) plays App/Audio.

`Shared/Sources` holds the app-side glue: `GameSession` (the save: load, append with trusted time, derive), `Visit` (which scene is on screen, the greeting bubble) and `GameWorld` (builds scenes from the art and the state). Scenes receive finished values (`RoomModel`, `ExteriorScene.Model`, a `BehaviourChoice`) and decide nothing.

### The world (step 4)
- HouseCatCore: `HomePlace`, `HomeSettings` (in the save), `HomeNow` (the home right now), `WorldMap` (projection and distances), `CitiesFile`, `BiomeRules`, `WeatherFile` and `WeatherRules` (simulated weather), `moveCost`.
- HouseCatGame: `HouseBuilder` builds the `HouseModel` from the save and `HomeNow` (window terrain, sky, light map, ground) and names the exterior scene for a home, biome and season.
- The app: `GameWorld.now(state:at:)` (with debug overrides), `WorldMapView` and `WorldMapModel` (MapKit search and reverse geocoding, the biome under the pin from the bundled mask), `GameSession.placeHome`.

### The widget (step 5)
- `Widgets/Shared` is compiled into the app and the widget: `WidgetFiles` (the App Group's `Widget/` folder: `snapshot.json`, `weather.json`, `Kit/`, `Inbox/`), `WidgetWorld` (the snapshot with the widget's own taps folded on, the app's Content read from the app bundle, the report and the kit), `WidgetIntents` (Feed and Pet) and `WidgetViews` (every size).
- HouseCatCore decides everything a widget shows: `WidgetRules.state`/`timeline` (pose, streak, fed), `WidgetRules.scene` (the pose's painting, the home's window, biome, season, sky and weather at that moment), `WidgetRules.event` (what Feed and Pet append). The widget only folds and draws.
- The app keeps its side current through `WidgetBridge`: the snapshot after each change (debounced), the kit when the look, home or biome changes (rendered off the main thread through `CatArt`), the inbox merged into the save each time the app becomes active (`GameSession.importEvents`, by event id, so a repeat is dropped).
- `RealWeather` asks WeatherKit for the pin's hourly forecast and stores a `WeatherReport` beside the snapshot; `GameWorld.now` and the widget both pass it to `homeNow`. `Reminders` schedules `ReminderRules.plan` with `UNUserNotificationCenter`.

### Mini-games and the nap (step 6)
- HouseCatCore: `MiniGameRules`, the three game models (pure, stepped by time, tested), `NapRules`. The reducer already paid `miniGamePlayed` (five a day) and `napCompleted` (once a day).
- HouseCatGame: `MiniGameScene` holds a game model, steps it each frame, draws it and passes the finger on; it reports progress, moments (for sounds and haptics) and the final score. The app's `MiniGameView` turns the score into stars and one `miniGamePlayed` event through `GameSession.playMiniGame`.
- The nap: `Naps` (Shared) keeps the nap in progress in the App Group, starts and ends the ActivityKit activity (`NapAttributes`, shared with the widget extension, which draws `NapLiveActivity`), and records `napCompleted` through `GameSession.completeNap` once the time is up.

### The outside (18 Oct)
- HouseCatCore `Home/Outdoors.swift`: `OutdoorsFile` (content), `OutdoorRules.sprite` (the season's picture) and `OutdoorRules.layout` (dart-throwing from the household's `DaySeed`, clear of every room by `Tuning.Outdoors.margin`, tall pieces only behind). HouseCatGame `HouseBuilder` lays the scenery out round the ground floor's rooms (`HouseModel.scenery`; `isSnowy` is shared with the ground tile), and `RoomScene.buildScenery` draws it in the world under the rooms when behind and over them when in front.

### Rooms (step 3)
- `RoomScene` builds a `RoomNode` for every room of the plan and puts the shown storey's in the world. `house.active` is the room you are in (`show(room:)`; the app's `Visit.go(to:)`), `catRoom` the cat's. `HouseModel.links`/`route` give the doorways between rooms side by side and the way through open ones; `RoomScene.route(to:)` turns that into director steps (walk to the doorway, `.enter` the next room's node, on) or, across storeys, out by the stairs with a fade.
- HouseCatCore decides which room an activity happens in (`RoomChoice`, from what each open room's furniture offers) and what the Bean shop sells (`BeanShop`); the app asks for both through `GameSession` (`nextActivity(catRoom:viewing:)`, `placed`, `shop(for:)`, `buy`).

### The cat builder and the coat recipe (step 2)
- `HouseCatCore`: `CatLook` (catbuilder.json's `look_fields` plus the weight slider; colours are palette names or picked "#rrggbb"), `CatBuilder` (the options a body allows, the weight slider, colours, which sprite draws each part and pose), `CatNames` and `NameFilter`, `CatProfile` (together days, age, trust, badges, anniversaries, lifetime stats). The builder's options come from `App/Art/cat/custom/builder.json`, the ordered copy of catbuilder.json that `build_cat_art.py` writes.
- `HouseCatGame`: `CatArt` loads a sprite's white painting and masks (`Raster` reads pixels as stored, no colour management) and `CoatRecipe` tints them with Accelerate; `CatNode` draws any look (and `apply(look:)` redraws it); `DressingRoomScene` (`Builder/`) is the creator's set: the painted dressing room zoomed so the cat stands on its podium in the middle of the space the controls leave open, turning round the podium, standing, sitting or close on the face for the drawer that is open, and reacting to each change (`CatPreviewScene`, the old sofa-and-rug preview, is no longer used). `HouseCatUI` `DressingRoomLayout` lays the room, the chest of drawers and the open drawer out for both the creator and the outfit catalogue (`App/Sources/OutfitCatalogue.swift`, which tries outfits on the cat with `DressingRoomScene.dress`; what each outfit is to the household is `HouseCatCore` `OutfitAvailability`).
- `HouseCatUI`: `CatBuilderModel` and `CatBuilderView` (adopt and edit modes), `CatProfileView`, `GiftBookView`.
- The app: `HouseCatApp` shows the builder when the save has no cat, then the visit; `RoomScreen` holds the room's controls and the profile, book, shop and Edit look sheets; `Visit` drops and collects the gift (`RoomScene+Gift`), and plays the level and trust moments.

## 5. Persistence

`EventStore` (HouseCatModels) keeps `StoredEvent` (the event as JSON, with its id, time and day index for queries) and `StoredSnapshot`. Every attribute has a default and nothing is unique, as CloudKit mirroring requires. The store lives in the App Group container so the widget reads it; mirroring uses the CloudKit private database `iCloud.com.housecatgame.housecat` once the iCloud capability is on the App ID (needs the developer account). No accounts, no login, no backend.

## 6. The store

`EntitlementService` (HouseCatStore) is the only thing the app asks about purchases:
- `StoreKitEntitlementService`: StoreKit 2 directly. `Transaction.currentEntitlements`, `.verified` only, revoked dropped, `Transaction.updates` listened to and finished.
- `RevenueCatEntitlementService`: RevenueCat on StoreKit 2; `entitlements.verification == .failed` means no entitlement. Used once `RevenueCatAPIKey` is set in Info.plist (empty until the RevenueCat project exists).
- Entitlements are held in memory and mirrored to the device Keychain (not synchronisable) so an offline launch knows what the player owns; the store's answer replaces the mirror on every refresh, so a refund strips the item at the next launch.
- `StoreCatalog` lists the three kinds of product (Josh, 18 Oct): five Bean packs (consumables) and the once-only starter, the room looks from `Content/bundles.json` (non-consumables), and Cat Club monthly and yearly in one subscription group with the 7-day trial as an introductory offer on yearly. `tools/store/build_storekit.py` writes the matching `Store/HouseCat.storekit`, and a test checks they agree.
- Purchases into the save: the service tells the app about each purchase that puts something in the save through `onGrant` (a `StoreGrant`: product and transaction id): as it happens, consumables bought while the app was closed (`Transaction.unfinished`, finished only after `onGrant` has taken them), and non-consumables on each refresh. The app's `GameSession.grant` appends `purchaseBeansGranted` or `bundleGranted`, which the reducer applies once per transaction id; Beans therefore sync to a co-owner like any other event, and a repeated grant changes nothing. `Entitlements` keeps only Cat Club, the starter and which looks are owned.
- `StorePrices` (App) loads the products once for the shop, the top-up, the look bar and the tray's money values.
- Paid furniture is placeable through `RulesContext.paidItems`; the scenes hide any paid item the player no longer owns.
- Seasonal stock (outfits with months) is listed only in its months, with its real last day, and comes back every year (`ShopRules`, `ShopProduct.isOnSale`). Owned items always show.
- `ProductInfo` carries StoreKit's `price` and currency code as well as its `displayPrice`, so the shop can show a plan's price a month and add up what a pack's parts cost on their own, always in the player's currency.

## 7. CloudKit sharing (designed now, built in the social milestone)

Sharing never goes through SwiftData. It uses raw CloudKit records in custom zones, shared with `CKShare`, holding small JSON documents. Each person's authoritative save stays in their own private database.

**Invites are one-time links.** Every invite, gift and cat-sitting link is a `CKShare` participant added with `CKShare.Participant.oneTimeURLParticipant()`, one slot per invitee, never `publicPermission`. Unaccepted slots are removed after 48 hours (`Tuning.Social.inviteExpiryHours`). Display names are chosen by the player (and pass the profanity filter); iCloud identities are never shown (iOS 26 hides participant names without a special entitlement anyway).

**The owner is the only writer of anything valuable.** Participants get read-only access to anything that grants items, Beans or progress. Where a participant must contribute (a co-owner's visit, a sitter's feed), they write a small request record to an inbox; the owner's device validates it (kind allow-list: arrived, fed, petted; dates; the sitter's 14-day window) and appends the real event to the owner's log, deduplicated by the request id.

| Feature | Zone (owner) | Records | Participants |
| --- | --- | --- | --- |
| Co-owning a cat | `household-<id>` (original owner) | `Inbox` requests from the co-owner; `HouseholdCard` (cat look parameters, house layout, level, streak) published by the owner | co-owner: read the card, write inbox requests. Both owners' arrivals count for the streak; the co-owned cat's time together counts from its original adoption |
| Groups (up to 12) | `group-<id>` (creator) | one `PresenceCard` per member (a few KB of JSON: cat look, house layout, level, streak, personality, display name), `PawPrint` (one per member per day) | members: read all, write only records they created (enforced in the client by `creatorUserRecordID`; cards can be rebuilt from each member's own save) |
| Cat-sitting | `sitting-<id>` (cat's owner) | `SittingWindow` (start, end ≤ 14 days), sitter `Inbox` feeds | sitter: read the window, write inbox feeds |
| Gift links | `gift-<id>` (giver) | `Gift` (SKU, status `sent` → `redeemed`) | one one-time participant, read-only; the gift becomes `redeemed` when that participant accepts the share. The recipient's own device records the item in their own save, so it restores on their devices; never re-giftable. (Paid gift products went with the 18 Oct money model; presents between co-owners are Bean outfits in the shared save.) |
| Friend codes | public database | `FriendCode` (record name = the code; the invite's one-time URL and its expiry, 48 h) | anyone with the code reads it; only its maker writes it |

Every group shows Leave, Remove member (the owner removes the participant from the share) and Report (emails safety@). No free text other than the cat's name, no leaderboards, no public map.

**Co-owning as built (for 1.1).** Co-owning syncs the household's events both ways: CKSyncEngine over the owner's `Household` zone, shared zone-wide; the co-owner writes to it through their shared database. It does not use the inbox requests above. The reducer settles what each owner did (refused purchases, taken cells), and only events travel, never entitlements. Membership is in the save: `coOwnerJoined`, `coOwnerLeft` and the owner's `coOwnerRemoved`, so a former co-owner's later events count for nothing. Joining sets the joiner's own household aside on their device, and leaving brings it back; the two are never merged. The owner stops sharing by deleting the share; a co-owner leaves by deleting the shared zone from their shared database. Report opens a pre-filled mail to safety@ with the household's reference (`HouseholdReference`). Hide is a per-device preference. CLAUDE.md, "Co-owning for 1.1".

## 8. Testing

- `swift test` in every package: HouseCatCore (rules, content validation), HouseCatModels (SwiftData store), HouseCatGame (grid maths, rig integrity, puppet build and hand-over, room build and draw order, cat spots, a full simulated arrival, exterior framing), HouseCatUI, HouseCatStore (entitlement mapping, product table, `.storekit` agreement). HouseCatGame's tests read the real `App/Art`.
- `HouseCatTests` (Xcode, hosted in the app, iPhone simulator): `GameSessionTests` (the save glue against an in-memory store: seeding, the arrival, feeding, the inventory, decorate records) and StoreKit with `SKTestSession` against `Store/HouseCat.storekit`, covering product types, the yearly trial, an outfit purchase that survives a relaunch, Cat Club, the season pass, gifts and refunds. The app does not start StoreKit when it is hosting tests (`XCTestConfigurationFilePath` is set), otherwise StoreKit binds to the sandbox before the test session loads the configuration.
- Build and run: XcodeBuildMCP in a session opened in the repo, or `xcodebuild` (commands in CLAUDE.md).
