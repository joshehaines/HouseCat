# HouseCat — cat virtual pet for iPhone (black-cat mascot)

Spec: @docs/SPEC.md (every number is a locked decision). Art inventory: @docs/ASSETS.md (assets are finished and confirmed before the code build; build against the real files). Content brief: @docs/CONTENT.md (lines, names, objectives, mini-game rules are generated from it as data). Art rules: @docs/STYLE.md. Keep @docs/ARCHITECTURE.md current. The name is HouseCat (chosen 17 Oct 2026). Product IDs use the `housecat.` prefix and are created once, correctly: App Store Connect never lets them be renamed.

## What this is
A painterly 2D pet game. Every visit starts outside the player's home in real weather; they tap the door, the cat (with a chosen personality) greets them; they feed, pet, play, collect gifts and furnish rooms the cat uses. Adults 25–40 first; rated 4+, not Kids Category. No ads. Full scope in v1: cat builder, world map with search and seasons, 8 houses, 6 rooms, 80 furniture, widgets with the visit streak (including the home-model widget), 3 mini-games, season pass (free + paid tracks), groups, co-owning and cat-sitting via CloudKit sharing, gifting, the stray, HealthKit layer, Siri/Shortcuts, Watch complication, iPad dollhouse view, Mac menu-bar cat, wallpaper and share-card exports. There is no timeline: work runs as ordered steps, each with an exit test (SPEC.md "Build phases"); nothing is staged out.

## Commands
- Generate project: `xcodegen generate` (the .xcodeproj is generated and git-ignored). xcodegen and git-lfs are Homebrew's: put `/opt/homebrew/bin` on PATH first, or git cannot read the art and xcodegen is not found
- App sounds from `assets/audio`: `tools/app-assets/build_app_audio.sh` (afconvert to AAC into `App/Audio`)
- App icon and launch logo from `assets/brand`: `tools/app-assets/build_app_assets.sh` (writes `Shared/AppIcon.icon` and the LaunchLogo image set; never edit the masters)
- Build without XcodeBuildMCP: `xcodebuild -project HouseCat.xcodeproj -scheme HouseCat -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -derivedDataPath ~/Library/Developer/Xcode/DerivedData/HouseCat-CLI build` (schemes: HouseCat for iPhone, iPad, widgets and Watch; HouseCatMac). Never build into the repo: it sits in ~/Desktop, and simulator apps then hang on macOS's Desktop-folder privacy check when loading frameworks
- Build/run/screenshot: XcodeBuildMCP tools in the iPhone and iPad simulators (Josh tests in the simulators, no physical device yet; widgets, Live Activities and the Watch app all run in simulators too)
- Core tests: `cd Packages/HouseCatCore && swift test` (every package under `Packages/` has its own `swift test`)
- StoreKit tests: `xcodebuild test -project HouseCat.xcodeproj -scheme HouseCat -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -derivedDataPath ~/Library/Developer/Xcode/DerivedData/HouseCat-CLI -collect-test-diagnostics never` (the app skips StoreKit at launch when it hosts tests, so `SKTestSession` can load the configuration first)
- If a StoreKit test hangs (usually the outfit purchase) the simulator is holding a stale sandbox sign-in prompt from a command-line launch: `xcrun simctl shutdown <udid> && xcrun simctl boot <udid>` and run again.
- Every control checked (the regression check for "a button does nothing"): `xcodebuild test … -only-testing:HouseCatUITests/ButtonSweepTests` on the iPhone 18 Pro Max and the 13-inch iPad (a Debug build; `TEST_RUNNER_SHOTS=<folder>` keeps the screenshots). `-only-testing:HouseCatUITests/WidgetTests` adds the medium widget to the Home Screen, presses Feed, Pet and Visit and takes it off again (simulator only: the widget needs the App Group)
- After changing the Bean packs or the room looks (`Content/bundles.json`), edit `Store/HouseCat.storekit` by hand to match. `tools/store/build_storekit.py` no longer makes today's file (it would cut the looks' descriptions short and rename the starter), so it leaves a differing file alone unless given `--force`.
- Format and lint: `swiftformat .` then `swiftlint`
- App art after changing what the game draws (SETS in the script) or any master it uses: `python3 -I tools/app-assets/build_app_art.py` (standard library and `sips`)
- Art tools in `tools/asset-pipeline/` need Python with Pillow, numpy and scipy (rembg for furniture cut-outs); the system Python has none, so run them as `uv run --with numpy --with pillow --with scipy python <script>`. Shop pictures: render on flat magenta, save as `raw_<name>.png`, then `shopkey.py <name>…` writes `v3/shop_<name>.png` for `assets/ui/shop`. `puppet.py` (rig by eye), `living_room.py` (room layout and scale by eye), `scenes.py` (exterior scenes: Higgsfield requests, keying, door points), `extract.py` (grey-room furniture cut-outs)

## Architecture rules (always)
- The save is an append-only EVENT LOG (fed at t, petted, placed item x, bought y, claimed tier n …). Every piece of state (trust, XP, Beans, streak, room contents, pass progress) is derived from the events + `DaySeed`; nothing is stored as a mutable counter. iPhone, widget, Watch, iPad and Mac all append events to the same iCloud save and never conflict. Compaction keeps a snapshot + the events since it.
- All state derives from timestamps + `DaySeed`, never from running timers; the app and the widget must compute the same state independently.
- Clock rules: a streak day is the local calendar day at the player's wake time; the sky uses the home's time zone; a backwards clock jump is ignored, a forward jump is capped at one day per real day.
- Scenes and widgets read state; they never compute rules. Rules live in HouseCatCore with a test before a screen.
- Every tunable constant lives in `Tuning.swift`. Never inline a magic number.
- Local-first: SwiftData in the App Group, CloudKit private-database mirroring, for the player's own save only. No accounts, no login, no backend.
- Sharing between people (co-owning, groups, cat-sitting, gift links) does NOT go through SwiftData: it uses raw CloudKit records in a shared zone (`CKShare`), small JSON documents (profile card, house layout, cat parameters, event deltas). Design in docs/ARCHITECTURE.md before the first line.
- Weather: fetch WeatherKit on arrival at most once an hour per home, cache three hours, show the Apple Weather attribution and link where weather is displayed. Widgets never fetch; they read the cached forecast.
- Places: the world map is a stylised painted globe that turns (blue sea, green land, no real terrain; a flat map until 18 Oct). Place search is MapKit's search completer (Apple Maps); no Apple Maps data is drawn on the map, and the cities it names are a hand-made list. The pin's coordinate generalises to one of the 8 biomes (city if near a listed city, else coast / countryside / mountain / forest / desert / tropical / snow from a coarse mask).
- Network only for RevenueCat, CloudKit, WeatherKit, PostHog, Sentry. Widgets never touch the network.
- Placeholder art (coloured shapes with correct footprints) is always acceptable; never block on a painting.
- No third-party dependency without asking. Allowed: RevenueCat, PostHog, Sentry.
- Commit after every working step with a one-line message; keep the build green.

## Product rules (never break)
- The cat never dies, never runs away, never loses trust, XP, Beans or items. A missed day = sulk animation + lines + no gift. Nothing else.
- Trust = count of fed days per cat (tiers 3/7/14/30/60/100). Level = player XP (thresholds in Tuning). Both only rise.
- Streak = consecutive days with a VISIT (an arrival in the app, or Feed/Pet from a widget). One free miss per rolling week; pause mode up to 14 days a quarter; a lost streak restarts at 1 and the longest streak is kept. Milestones 7/30/100/365. The streak number and the "visited today?" cat pose are on every widget (SPEC.md "Widgets, the Duolingo layer").
- Cats are built in the cat builder: body (shorthair or longhair with the weight slider, Persian, Siamese, Maine Coon, Sphynx), ears, tail, any coat colour, pattern, white markings, eye colours (odd eyes allowed), eye size, nose, whiskers, age, or a one-tap preset. Midnight, the black cat, is the mascot, the default and the first preset (decided 17 Oct 2026: full customisation replaces "all cats are black cats"). Every field is re-editable later for free. Every builder option is free at launch; extra cats are not sold yet (the cat-slot products went with the 18 Oct money model; how a second cat is paid for is undecided). The player always names their own cat; preset names name the look. Looks are composed from the WHITE part sets in `assets/cat/custom` + pattern / white / feature masks + the coat-recipe shader + scales, never separate paintings per look. `catbuilder.json` is the data; `tools/asset-pipeline/tint.py` is the reference the shader must match (SPEC.md "Coat recipe").
- Time together: the cat's profile shows days together since adoption and the cat's age, derived from the adoption event and `DaySeed` (no stored counter). It only ever rises: misses, lost streaks and pause never touch it. Gotcha day on each anniversary (SPEC.md "Age and time together").
- Onboarding order is fixed: landing page → cat creation → geography (painted world map with MapKit place search, then season) → house selection and design → first arrival.
- The home's pin decides terrain (biome mask), local time (time zone), weather and hemisphere season. Season = Auto or a fixed season; a fixed season simulates weather from the biome's seasonal table instead of WeatherKit. No CoreLocation anywhere.
- The exterior is ONE layered scene (sky in code, terrain painted per biome per season at noon, house painted once at noon, overlays, weather and season particles), colour-graded in code for time of day, and every room's window renders that same scene through a mask. Never paint per time of day.
- The arrival in the room view is live: the cat notices you, runs towards the camera (front view, scaled up along the run), rubs along the bottom edge (side view crossing, purr, haptic), then picks its next activity from the behaviour table (mood × weather × personality → an affordance + a pose) and walks to the furniture that has it. Rooms are alive: items carry a `motion` entry (sway, bob, glow, spin, frames) and the room runs idle life (dust in the sunbeam, rain on the glass, steam, the lamp at dusk).
- First arrival: the house is EMPTY apart from the cat. One room open; a housewarming allowance (Tuning: 150 Beans) furnishes it. Every further room needs a level AND Beans above the allowance (Tuning: bedroom L2+200, kitchen L3+300, garden/balcony L6+800, study L9+1,500, attic L12+2,500); money never skips a level (Cat Club halves the Bean cost only). Locked rooms show as lit silhouettes with level and price.
- Beans are the one currency: earned every day in play AND sold in packs, like a builder game's gems (Josh, 18 Oct 2026; this replaces "earned only"). They never expire and are shared by the household. A Bean price is shown with what it comes to in money at the smallest pack's rate (EU CPC principles on in-game currencies). The daily gift is earned only and never purchasable (no loot-box rules apply). Nothing random is ever sold. No player-to-player marketplace; duplicate earned gifts can be swapped inside a group or sold back for Beans.
- Four kinds of product (Josh, 18 Oct; the pass 19 Oct): Bean packs (consumables, `housecat.beans.<size>`, each bigger pack more Beans a pound, plus the once-only `housecat.starter`), room looks (non-consumables, `Content/bundles.json`, a whole room's pieces, wallpaper and floor), each season's premium pass (non-consumables, `housecat.pass.<season>`, the main thing sold), and Cat Club (the one subscription, which includes every season's premium track). Everything else (outfits, single pieces, presents for a co-owner) is bought with Beans, and when Beans fall short the button becomes Top up with the smallest pack that covers it. Paid items are deterministic and shown with their real price. No weekly plans. No countdown timers except an event's or season's real end date (`events.json`).
- Season pass, the main progression (Josh, 19 Oct; "The season pass" below): a season always running, four weeks each, back to back; thirty tiers climbed with the XP earned while it runs plus the goals' bonus pass XP; a free track to tier 20 and a premium track to 30; every reward fixed and visible from day one. Premium is each season's own purchase (`housecat.pass.<season>`) and comes with Cat Club too (a club day, `clubDayRecorded`, appended each launch while the subscription is active); buying mid-season opens every tier already reached; items earned on it are kept forever.
- The stray: a second cat appears at the window on a monthly cadence from `DaySeed` (weekly with 3+ cats), only after a second room is open and furnished; adopting needs a spare bed in a room beyond the first; look is deterministic from the seed; never adopted = comes back another month. How adopting is paid for is undecided since the cat slots went (18 Oct).
- Groups: up to 12 members via a CloudKit share; profile cards (cat params, house layout, level, streak, personality) as small JSON rendered locally; read-only visits, one paw print a day; cat-sitting (feed a member's cat up to 14 days) and gift links live inside groups. No public map, no free-text chat, no backend. No leaderboards, rankings or competitions anywhere (that alone would move the age rating from 4+ to 13+); the only user-authored text visible to others is the cat's name, passed through a profanity filter. Every group has Leave, Remove member (owner) and Report (emails safety@) — the Online Safety Act treats a group as a small user-to-user service.
- Sharing mechanics: invite, gift and cat-sitting links are one-time CloudKit share URLs (`CKShare.Participant.oneTimeURLParticipant`, never `publicPermission`), one slot per invitee, unaccepted slots expire after 48 h; the share owner is the only writer of anything valuable; each member's authoritative state stays in their own private zone and the group zone holds only small presence cards that can be rebuilt. Player-chosen display names, not iCloud identities (iOS 26 hides participant names without a special entitlement).
- Gifting (Josh, 18 Oct): presents are outfits bought with Beans by one co-owner for the shared cat (`outfitBought(gift: true)`), found wrapped at the other owner's next arrival. No gift products for money, no founders' pack and no lifetime unlock any more.
- What a purchase puts in the save (a pack's Beans, a room look's pieces) goes in as an event keyed by the transaction id, once (`purchaseBeansGranted`, `bundleGranted`); a Bean pack is finished with StoreKit only after it is handed over. Entitlements (Cat Club, the starter, which looks are owned) are derived on launch from verified StoreKit transactions (`.verified` only, `Transaction.currentEntitlements`, RevenueCat `verificationResult == .failed` ⇒ no entitlement), held in memory, mirrored to the Keychain for offline use, and NEVER written to the synced store (a share participant could otherwise mint items). Revoked or refunded transactions strip the item on the next launch.
- Trusted time: never trust `Date()` alone for streaks, gifts or cooldowns; anchor on CloudKit `modificationDate`, StoreKit `signedDate` and system uptime; a wall clock that jumps backwards or more than a day ahead of the anchor pauses game time instead of punishing.
- Exports (wallpaper, streak cards, Sunday card) render on device from the current state. Wallpaper options are the player's choice; the app mark is on by default and can be turned off. No time-lapse.
- The widget scene is the cat sitting in the window: the player's cat (its look, back or side view) in their house's window frame, with the real weather and time of day behind the glass, streak and "visited today?" pose on top. No room rendering in the widget; the window frame per house and the cat poses are pre-rendered PNGs in the App Group.
- Other surfaces share HouseCatCore and the iCloud save: Watch complication, iPad dollhouse view, Mac menu-bar cat (Feed/Pet there count as the visit), Siri/Shortcuts via App Intents. Every surface reads state; none computes rules.
- Personality (Aloof, Velcro, Gremlin, Loaf) changes lines and behaviour weights only; it never changes economy numbers.
- Health data (steps, sleep, workouts) is opt-in on day 3 and only ever rewards. It is presented as passive rewards ("your cat walks with you"), never as exercise advice, goals or recommendations (that answer moves the age rating to 9+). Raw samples never leave the device: only derived flags ("walk goal met") sync, in `allowsCloudEncryption` fields; no health value ever reaches analytics (Apple 5.1.3). Request each HealthKit type only when its feature is first switched on.
- Notifications are local, user-scheduled, opt-in via a pre-permission screen after the first feed. Season and event announcements are marketing and have their own separate opt-in toggle (Apple 4.5.4).
- Analytics (PostHog, EU-hosted) is OFF until the player switches it on in the cat's settings (UK AADC: high privacy by default; changed in step 10), and off entirely until a key is set; anonymous IDs only, no session replay, Sentry PII scrubbing on. A "Delete all my data" action wipes the local store, the CloudKit zones and the vendor records by the anonymous ID shown in Settings; "Export my data" shares a JSON of the save.
- Text boxes and meows only; no voice. Lines come from `lines.json`, never hard-coded.

## Art rules (summary; STYLE.md is authoritative)
- Painterly and colourful (high-key, saturated), warm key light, rim light on the fur, amber eyes; slim body, round head, big eyes, both ears upright; slightly stylised, never a cartoon mascot.
- Rooms are 2:1 isometric corner rooms (10 × 10 floor, walls 5 high, a door to the next room), built in code from flat wall/floor tiles projected onto the two walls and floor, multiplied by a painted light map (morning, midday, evening, overcast, night). Furniture sprites come in R and L orientations, all painted in the grey reference room at true 2:1. The cat is a cut-out puppet (painted parts per view) posed and animated in code, handing over to painted resting poses with a cross-fade; walking and running it is a film of a white cat tinted into its look (below, "The walk and run are films"). The exterior is one painting per home × biome × season, the sky and time-of-day grade drawn in code.
- Never: red bow/collar, white-sclera almond eyes, crescent forehead mark, witch hat, Ghibli greens-and-cream palette. Never name a cat Jiji, Luna, Salem, Binx, Figaro, Felix.

## Decisions during milestone 1 (17 Oct 2026)
- Exteriors (Josh: the isometric façade never sat on the eye-level terrain; "Higgs every option"): every home is painted into every biome and season as one picture from a raised three-quarter view (`tools/asset-pipeline/scenes.py`, 8 × 8 × 4 = 256, plus a door-open edit of each). Stored as `assets/world/scenes/<house>_<biome>_<season>.jpg` with `_land.png` (sky mask) and `_glass.png` (window glass); `scenes.json` holds each door point, measured from the door-open edit. The façades in `world/houses` and the terrain backdrops stay for the window view and the widget.
- The living-room furniture was repainted in the grey reference room (Josh: the cream-room sofa did not sit on the grid; those originals were not true 2:1). Every room now uses one painted scale per reference room (`refScale` in the layout, grey 0.46).

## Co-owning for 1.1: leaving and removing, reporting, and switching it on (19 Oct 2026)
Josh, 19 Oct: co-owning stays hidden in 1.0. It has never run end to end, it needs the developer team and the iCloud container, and it lacked the Leave, Remove and Report controls App Review 1.2 expects. It leads 1.1. The code side is ready and off; what is left is below ("To switch sharing on"). The website and App Store lines it needs are in `docs/appstore/sharing-1.1.md`.
- Leaving and removing: who looks after the cat is in the save. `coOwnerJoined` is a co-owner's first event after accepting. `coOwnerLeft` comes from a co-owner (the owner never leaves; they stop sharing). `coOwnerRemoved(key)` counts only from the owner. `HouseholdState.owners` is who is in now and `formerOwners` who left or was removed. Anything a former owner does afterwards counts for nothing until they join again (`MembershipTests`). Leaving takes nothing from the household: the streak, the Beans (earned or bought by either owner), the furniture, the presents and the visits already made all stay. The shared quest goes once only one owner is left (`CoopQuest` now counts owners now, not this week's visitors).
- The owner has Stop sharing, in the Together card and in Settings' Share card once someone has joined (`HouseholdSync.stopSharing`). It writes `coOwnerRemoved` for each co-owner, then deletes the zone-wide share (unused invite links die with it) and the friend code record. Co-owning is for two: once someone has joined, the Share card shows who instead of offering another invite.
- A co-owner has Leave (`HouseholdSync.leave`): `coOwnerLeft` is sent, then they leave the share by deleting the shared zone from their shared database. Chosen for Josh's "keep or start their own": the shared cat stays with its owner, and the leaver gets back the cat they had before joining, or adopts a new one through the intro. A copy of the shared cat is never kept, since it would duplicate Beans the other owner bought. So joining sets the joiner's own household aside (`GameSession.joinShared`: the log as JSON, `Application Support/HouseCat/own-household.json`) and never merges it. Both households' cats are `midnight`, and before this, joining merged two saves into one. `returnToOwnHousehold` brings it back. Days away count as days away (its streak may have ended), and the join card says so. One household at a time: a co-owner, or an owner who shares, can't take another invite (`HouseholdSync.joinBlocked`).
- Being removed: a co-owner's phone sees the shared zone go (`fetchedDatabaseChanges`) or the owner's `coOwnerRemoved` come down (`checkMembership`). It then goes home with a notice (`SharingNotice`). An owner's phone records co-owners as gone once the share has no accepted participant left (`settleMembers`), for a co-owner who left offline or deleted the app.
- Report and hide (App Review 1.2). Report, in the Together card and under an opened present, opens the person's mail app to `Tuning.Store.safetyEmail` with the message filled in (`SafetyReport`: what it is about, who, the cat, the household's reference `HouseholdReference.code`, the app version). With no mail app, the address and reference are shown. Hide is a device preference (`HouseholdSync.hidden`): it shows a co-owner as "Pip's other owner" and stops their paw prints and presents being announced (the outfit is still in the wardrobe). The owner has no typed name, so a co-owner gets only Report and Leave. Real blocking is Stop sharing or Leave.
- The join card's name is player-chosen, through `CatNames.check` and `Tuning.Cat.nameMaxLength` (now also capped as it is typed). It can't be changed later, because it is the co-owner's actor key that the quest and the history count by, and the card doesn't say it can.
- Delete all my data, as a co-owner (`HouseholdSync.deleteHousehold`): `coOwnerLeft`, out of the share, then their own household zone, their friend code record and the cat set aside. Their past events stay in the owner's household under the name they chose, since they are the history the streak counts. The privacy lines say so.
- Sync fixes made on the way: a co-owner's records go to the owner's zone (its `ownerName`, kept at accept). Events queued before the engine is up wait for it. A record is built from the save by event id, so pending sends survive a relaunch. An owner's whole save goes up the first time the engine runs (events from before sharing was on; `sync.private.uploaded`). Events fetched from CloudKit are never sent back up (`importEvents(fromCloud:)`). Accepting fetches the household before the switch, so the cat is there when the room opens (`.houseCatSwitched` rebuilds the first screen).
